# Canary releases and openplan update --canary

Publish a canary build of the CLI and the daemon from each push to `main`.
`openplan update --canary` installs the newest canary build.

Each push to `main` replaces one prerelease. `openplan update --canary` reads it.

```d2
main: push to main
workflow: canary.yml
release: "GitHub prerelease, tag `canary`"
cli: openplan update --canary
main -> workflow
workflow -> release: replaces the assets
cli -> release: releases/tags/canary
```

## Design

- **One rolling prerelease.** A new workflow `canary.yml` runs on each push to
  `main`. It builds the same artifacts as `release.yml`: the `openplan` archives
  and their `.sha256` files. It moves the tag `canary` to the pushed commit and
  replaces the assets of the prerelease `canary`. The release list keeps one
  canary entry. `releases/latest` skips a prerelease, so `openplan update`
  does not see the canary build.
- **Version.** The canary build has the version `<next patch>-canary.<run>`,
  for example `0.4.1-canary.57` after `0.4.0`. `<run>` is the GitHub run
  number, so each canary is newer than the one before it. SemVer puts the
  canary after the last stable release and before the next one. The release
  title holds the version, because the tag `canary` does not. The workflow sets
  the version only in the build. It commits nothing.
- **`openplan update --canary`.** The command reads `releases/tags/canary`,
  takes the version from the release title, and installs the build when it is
  not the installed version. The download, the digest check, the order of the
  steps, and the refusal of a binary it does not own stay as in
  [[./00108-self-update-the-cli-and-the-desk.md]].
- **Back to stable.** `openplan update` with no flag installs the newest
  stable release. On a canary build that can be an older version. The command
  then says that it goes back from the canary to the stable release. The
  channel is not stored. The flag chooses it on each run.
- **`openplan --version`** shows the canary version as it is, so a bug report
  names the exact build.
- **No app.** Releases carry no desktop app now. The canary build carries the
  CLI and the daemon only. `--canary` skips `OpenPlan.app` as `update` does.

## Constraints

- This changes the rule "one command, no flags" in
  [[./00108-self-update-the-cli-and-the-desk.md]].
- `release.yml` is generated by cargo-dist and starts only on a version tag.
  `canary.yml` must not trigger it. The tag `canary` does not match its pattern.
- A canary build must not break a stable install that does not ask for it.

## Tests

- `op-update` tests use `Github::at` with a local server. They cover the canary
  release, a title that is not a version, and a canary build that goes back to
  stable.
