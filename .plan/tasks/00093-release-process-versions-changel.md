# Release process: versions, changelog, and cross-platform binaries

Ship `openplan` from GitHub. One tag makes one release with binaries for macOS and
Linux, release notes, and a one-line installer.

## Design

- **One version.** `[workspace.package] version` is the product version. All crates
  use it. `openplan --version` prints it through clap. The first release is `0.0.1`.
  Versions follow semver. No crate goes to crates.io, so every crate sets
  `publish = false`. The license is MIT, and `LICENSE` holds the text.
- **Changelog.** A person writes `CHANGELOG.md` by hand, in Keep a Changelog
  format. The GitHub Release notes come from the section for that version, so this
  file is the release page.
- **Bump.** `mise run release <version>` bumps the workspace version and commits. It
  stops when `CHANGELOG.md` has no section for the version. It prints the `git tag`
  command. A person makes the tag after the merge, because the release commit changes
  its hash on the way to `main`.
- **Build.** The tag `v*` starts `.github/workflows/release.yml`, generated by
  cargo-dist. Targets: `aarch64-apple-darwin`, `x86_64-apple-darwin`,
  `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`. Each job builds the web
  SPA first, because `op-server` embeds `web/packages/app/dist` at compile time.
  A build with an empty SPA folder must fail.
- **Install.** cargo-dist makes a shell installer. Users run one `curl | sh`
  command. A composite action in `.github/actions/setup` puts the binary on PATH in
  other repositories' CI.

## Constraints

- Windows does not compile. `op-cli` uses `nix`, unix signals, and
  `std::os::unix::process::CommandExt`. `op-store` uses `MetadataExt`. Windows needs
  a separate porting task.
- The repository must become public. A private repository has no anonymous
  downloads, so the installer and the composite action cannot work without a token.
- CI does not build or test the Rust workspace today. Add that job first. A tag must
  not be the first `cargo build`.
- `Cargo.toml` names the wrong repository. Correct it to `sukovanej/open-plan`.

>   GitHub reads every file in the workflows directory as a workflow, and this one is a
>   step list. cargo-dist also drops `working-directory` from those steps, so the SPA step
>   runs `cd web` itself.

>   working binary, and cargo-dist adds the directory to the shell profile. cargo-dist
>   refuses to combine `CARGO_HOME` with a second path, so there is no fallback.
> - `git-cliff` puts the compare link in the version heading, not in a link list at the
>   foot of the file. `--prepend` drops the footer, so the links would go stale.
> - I seeded `CHANGELOG.md` for 0.0.1 by hand. The repository has no tag, so
>   `git cliff --unreleased` would have listed all 176 commits.
> - I left the repository private. The plan needs it public. That is your call to make.

> four workflow files parse as YAML, `dist plan --tag=v0.0.1` lists the four targets, and
